# 07 UAT 受入試験仕様書

## 受入方針
プロジェクトオーナー自身が要件原文と乖離の説明を読むだけで正しい選択を行えるかを確認する。権威は既存の要件文書にあり、Agentの推論やキャッシュにはない。

| ID | 利用者操作 | 受入基準 | 承認欄 |
|---|---|---|---|
| UAT-001 | 既存要件フォルダを設定 | 手動で2200文書を分類する必要がない | 未実施 |
| UAT-002 | OCR禁止に反する新要求を送る | 関連要件の文書/行/原文の最小要約が提示される | 未実施 |
| UAT-003 | 選択肢Aを選ぶ | 承認済み要件は変更されず、修正方針を説明できる | 未実施 |
| UAT-004 | 選択肢Bを選ぶ | 要件改訂提案と影響説明を得られるが自動更新しない | 未実施 |
| UAT-005 | 選択肢Cを選ぶ | 実験と正式基線が分離される | 未実施・追加実装対象 |
| UAT-006 | 要件を密かに書き換えてPR | Ownerレビュー/CIで停止 | 未実施 |
| UAT-007 | 意味的に曖昧な短文で質問 | 誤って「完全一致」と断言しない | 未実施 |

## 合否
オーナー署名・受入日・環境バージョン・対象ベースライン digestを記録。MVPは「候補比較器」のため、意味的に網羅的な乖離検出を必要とする本番要件では補強・再UATを必須とする。
