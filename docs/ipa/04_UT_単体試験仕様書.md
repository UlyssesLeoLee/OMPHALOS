# 04 UT 単体試験仕様書

## 試験方針
Rust `#[test]` を単体の基本手段とし、決定規則・ID抽出・否定処理の境界条件を対象にする。正常/異常/境界/リグレッションを区別。実行時にJUnit等の形式に変換した結果を証跡保存すること。

| ID | 対象 | 入力条件 | 期待結果 | 自動化 |
|---|---|---|---|---|
| UT-001 | Parser | `[REQ-A-1]` を含む `##` | 指定ID抽出 | `parse.rs` 実装済テスト |
| UT-002 | Parser | `##` 付きIDなし | AUTO ID、再実行で安定 | `parse.rs` 実装済テスト |
| UT-003 | Parser | fenced code内の `##` | 見出しと扱わない | `parse.rs` 実装済テスト |
| UT-004 | Comparator | 禁止OCR要件 + OCR追加 | conflict/block | `engine.rs` 実装済テスト |
| UT-005 | Comparator | 禁止OCR要件 + OCR削除 | blockしない | `engine.rs` 実装済テスト |
| UT-006 | Comparator | コード候補 `ocr.process()` | 証明扱いにしない | `engine.rs` 実装済テスト |
| UT-007 | Parser | 同一REQ-IDを複数ソースに記載 | 例外 | 追加予定 |
| UT-008 | Parser | ソースパス外部への symlink | 読込拒否 | 追加予定 |
| UT-009 | Baseline | digest改ざん | 読込失敗 | 追加予定 |
| UT-010 | Cache | 同入力・同要件digest | 同一結果を返す | 追加予定 |

| UT-012 | Formatter | 3件超候補 | 最初3件のみを表示 | 追加予定 |

| UT-015 | Audit | 前レコード存在 | previous_hash参照 | 追加予定 |

## 試験手順
1. `cargo test -- --nocapture`。
2. 重要なケースはCIに配置してビルド後に自動実行。
3. 想定外成功/失敗は障害票を作成して原因と修正方針を明示。

## 合否
実装済み UT 全件成功が必須。未実装テストを「Pass」と書かない。対象機能別の網羅率/境界ケースを追加し、本番導入前にUT-007〜015を自動化する。
