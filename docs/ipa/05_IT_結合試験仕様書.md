# 05 IT 結合試験仕様書

## 目的
要件原本→抽出→Approved Baseline→Hook→MCP→Git/CI の結合を検証。外部Agent本体への接続は別の実環境ITで確認。

| ID | 組合せ | 手順 | 期待結果 |
|---|---|---|---|
| IT-001 | Parser+Store | demo config→init→TTY approve | approved.jsonを生成、IDとsourceが一致 |
| IT-002 | Store+Comparator | OCR追加promptを check | REQ-QC-001が出現しconflict/block |
| IT-003 | Hook+Comparator | UserPromptSubmit JSONをstdin送信 | `decision:block` と根拠/選択肢 |
| IT-004 | Hook+Decision | Conflict→`讨论 Concept` | 既存の未決情報をコンテキスト提示、書込は禁止 |
| IT-005 | MCP+Store | initialize/list/call(get) | 4ツール、原文と位置 |
| IT-006 | MCP+Decision | concept_decide(B) | proposal_only; Approved baselineは不変 |
| IT-007 | Git+Guard | 要件を無断変更 | check-baseline非0 |
| IT-008 | Git+Guard | 段階追加したOCR実装 | scan-staged候補警告（証拠不足） |
| IT-009 | Plugin+Host | Claudeでprompt Hook | 正常時参照注入、衝突時停止 |
| IT-010 | Plugin+Host | Codexでprompt Hook | 配布元信頼後に期待どおり |
| IT-011 | Error+Hook | バイナリ存在せず | 宿主 fail-closed を確認 |
| IT-012 | Multi-branch | Approvedに対し別worktreeで無断変更 | CIが変更を捕捉 |

### MCPスモークテスト
```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"test","version":"1"}}}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"requirements_get","arguments":{"id":"REQ-QC-001"}}}
```
各行をstdioへ順番に送信。1～3のJSON-RPC response idを確認し、ツール結果の `content[0].text` に要件ソースを含める。

## 合否
IT-001～008が成立し、使用する全宿主でIT-009～011が実機確認されるまでは正式導入不可。IT-012はGitHub等の受保護ブランチ設定を含む。
